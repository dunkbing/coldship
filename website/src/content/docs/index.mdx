## Why Coldship

Most self-hosting platforms are built for people clicking through a dashboard. Agents work differently. They can't see a UI, they retry blindly, they get confused by vague errors, and they will occasionally do something destructive with total confidence. Coldship is designed around that.

<CardGrid>
  <Card title="Plan, then apply" icon="list-format">
    Every change starts as a dry-run plan with a diff that marks what is destructive. Agents apply by plan id, so they
    can only apply what they reviewed. [Learn more](/concepts/plan-and-apply/)
  </Card>
  <Card title="Humans approve the dangerous parts" icon="approve-check">
    Destructive changes to production apps wait for a human with an admin token. Agents get no approve tool.
    [Guardrails](/concepts/guardrails/)
  </Card>
  <Card title="Errors written for LLMs" icon="comment-alt">
    Every error has a stable code, a hint and often a concrete suggested fix such as `{"port": 3000}`.
    [Error reference](/reference/errors/)
  </Card>
  <Card title="One-call debugging" icon="magnifier">
    `diagnose` returns container state, the last deploy, recent logs and likely causes, all sized to fit in an agent's
    context. [Debugging](/concepts/debugging-and-rollback/)
  </Card>
  <Card title="MCP built in" icon="puzzle">
    `coldship mcp` exposes ten tools to Claude Code and other MCP clients, acting under the agent's own scoped token.
    [MCP tools](/reference/mcp-tools/)
  </Card>
  <Card title="Deploy from Git" icon="github">
    Point an app at a repository with a Dockerfile. Plans pin the commit, failed builds never touch the running app, and
    rollbacks reuse built images. [Build from Git](/guides/build-from-git/)
  </Card>
  <Card title="One binary, self-hosted" icon="laptop">
    Server, CLI, MCP server and dashboard ship as a single Go binary. State lives in one SQLite file next to Docker.
    [Architecture](/project/architecture/)
  </Card>
</CardGrid>
